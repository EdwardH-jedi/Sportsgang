Key semantics (details in CONTRACTS.md):

- Handicap stored as signed tenths (`+2.1` → `-21`, no `>= 0` rule); pace as
  integer seconds/km (`"6.30"` rejected client- and server-side); `social`
  is a mode, never pace 0.
- `preferences_version IS NULL` = not configured; the migration writes no
  values; compatibility is never claimed for unconfigured rows.
- `level` stays required; the v2 UI asks "Overall level" explicitly (never
  derived from handicap/pace).
- Session preferences are informational; only status and capacity block
  joining (enforced under the existing `SELECT … FOR UPDATE`). Capacity is
  the total including the auto-joined host.

## 7. PostgreSQL concurrency (real services; mocked tests listed separately)

`tests_integration/test_event_capacity.py` on disposable PostgreSQL 16 +
Redis 7 (no dependency overrides; users registered through `/auth/register`
from distinct client peers so the Redis rate limiter stays enabled):

- three users race for the last place, repeated 5×: exactly one 200, two
  422 "Event is full", final `participant_count == capacity` every time;
- the same user joins 3× concurrently: one 200, two 409, count +1 only;
- host cancel concurrent with another user's join: always ends `cancelled`
  with a count consistent with whichever operation won the row lock;
- a join while another connection holds `SELECT … FOR UPDATE` on the event
  row stays blocked until release — proving the race tests really run
  concurrently;
- running host creates a session, another account joins/leaves, both
  `GET /events?mine=true` lists agree.

`tests_integration/test_run_golf_v2_journey.py`: two-account running
journey to a confirmed booking with old-client payload safety; golf
bilateral intents incl. legacy `needs_setup`, blocking; cursor paging with
an action between pages (no skip, no duplicate).

Mocked / SQLite tests (not proof of PostgreSQL locking): the 729 unit tests
in `apps/api/tests`, including the 109 new v2 ones.

## 10. Remaining defects, limitations, assumptions, deferred work

### 10.1 Known limitations (documented, not hidden)

- **Bounded pool.** Discovery still scores the newest 200 users with a
  profile for the sport; `total` counts eligible rows inside that pool and
  the UI says so ("We check the 200 newest … members"). Rare edge case: if
  acting on cards lets a 201st user enter the pool with a better sort key
  than the cursor, that user is only seen after a refresh.
- **1:1 booking composer** (existing flow from chat) still uses device-local
  time and the court-oriented venue picker; v2 group sessions use Sydney
  time. `CalendarPicker` greys past days by device date (the form still
  rejects past/impossible Sydney times).
- Legacy battle/challenge/tournament/honor/public-profile screens remain
  registered but unreachable from the v2 UI (cleanup is follow-up work).
- Session editing does not exist (cancel and recreate).
- Partner (identity) preferences are saved but not used for matching; the UI
  says so.
- The tab bar is label-only (no icon set is bundled; pre-existing).

### 10.2 Not verified (environment / scope)

- Software-keyboard overlap: the simulator had a hardware keyboard
  connected and the display was locked, so the on-screen keyboard could not
  be shown. Forms use `Screen withKeyboard` (KeyboardAvoidingView + scroll)
  and typed text stayed visible, but overlap is **not visually confirmed**.
  Repro: Simulator → I/O → Keyboard → uncheck "Connect Hardware Keyboard",
  open Explore → Host a run → focus Notes.
- Android, Expo dev-client builds, push notifications, Apple sign-in and
  account deletion were not exercised natively (their existing unit tests
  pass). Offline/request-failure states are covered by unit tests, not
  device runs.
- Device-timezone independence is proven by unit tests (process TZ set to
  Seoul / Los Angeles / UTC / Perth), not by changing the simulator TZ.

### 10.3 Assumptions

- Default similarity tolerance 5.0 strokes; "more experienced" = handicap
  ≥ 5.0 lower when both are numeric, otherwise a higher stated experience
  band.
- Overall level remains an explicit question in the v2 flow.
- Golf groups are 2–4 total and runs 2–50 total, including the host.
- Display names in dev data use a `[DEV]` prefix via the API (the app's own
  name sanitizer would not accept brackets).
